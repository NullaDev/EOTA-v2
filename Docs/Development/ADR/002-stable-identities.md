# ADR-002：稳定身份与分配顺序

- 状态：Accepted
- 日期：2026-09-04
- 接受日期：2026-09-06

## 决定

局内对象使用强类型整数 ID，不使用对象地址、默认哈希、系统时间或随机 GUID。

- `PlayerId` 固定为规则席位 0 和 1。
- `CardPrototypeId` 是经过校验的稳定 ASCII 标识。
- 开局时按 PlayerId、CardPrototypeId 和副本序号规范排序，为 `CardInstanceId` 递增分配无符号 64 位整数；随后只洗牌 ID 序列。
- `CardInstanceId` 标识一次具体的卡牌实例生命周期；`EntityId` 标识该实例当前在战场上的实体身份，二者不能互换。
- 新建对象在提交阶段按获胜 IntentId 的规范顺序分配 ID。
- 命令、计划项、帧、工作项、意图、冲突组、回执、事件和 Tombstone 均有独立强类型 ID 或稳定复合 ID。
- 所有 next-id 计数器属于权威状态并参与状态哈希。

外部 `MatchId` 可以由 Server 生成，只用于路由；它不决定局内规则身份。

## 回手

回手不是把战场实例原样搬到手牌：

1. 读取实体在回手裁决时的当前 `CardPrototypeId`。
2. 原 `EntityId` 离场，原 `CardInstanceId` 结束其生命周期并保留在历史/回执中。
3. 在手牌中分配全新的 `CardInstanceId`，其卡牌原型与步骤 1 相同。
4. 新实例不继承当前生命、伤害、Buff、临时关键词或其他实体状态。

若手牌容量裁决使回手失败，原实体死亡，原卡牌实例进入弃牌区；记录死亡墓碑并触发死亡及普通离场效果，不分配新的卡牌实例 ID。

## 变形与替换

- Transform 是实体原位改变形态：保留 `CardInstanceId` 和 `EntityId`，修改当前卡牌原型／形态，不产生死亡或离场事实。原始卡牌原型仅作为来源追踪信息保留。
- Replace 会使旧实体离场，并为进入槽位的新对象分配新的实例/实体身份；精确区域去向由对应 Intent 回执记录。

这样，规则身份与玩家可理解的生命周期一致，也避免“没有离场的变形”在实现中偷偷删除再新建实体。
