# ADR-011：自动移动的方向选择与槽位竞争

- 状态：Accepted
- 日期：2026-09-07
- 接受日期：2026-09-07
- 来源：从 [ADR-010](010-p4-system-gameplay.md) 拆分，保留已确认语义。

## 背景

自动移动需要分别决定“尝试进入哪条路线”和“多个随从争用目标时谁成功”。这两个选择不能由实体遍历顺序隐式决定。

## 决定

- `skirmisher` 在本路有敌随从时寻找没有敌随从的相邻路线；`pursuit` 在本路没有敌随从时寻找有敌随从的相邻路线。
- 候选必须是移动帧开始时空闲的己方随从槽。同帧移走的随从不会提前腾出可用槽位。
- 方向偏好与冲突优先级分别由协议配置，省略时使用下表默认值。

| 配置 | 可用值 | 默认值 |
|---|---|---|
| `movementDirectionPreference` | `outwardFirst` 向外优先、`inwardFirst` 向内优先 | `outwardFirst` |
| `movementConflictPolicy` | `centerFirst` 靠中心优先、`outsideFirst` 靠外侧优先、`allFail` 全部失败 | `centerFirst` |

中心/外侧优先比较来源路线到全场中心的距离，不使用玩家、EntityId、IntentId 或枚举顺序产生胜负优先级。两种位置优先策略都要求总路线数为偶数，由协议编译器拒绝奇数配置；allFail 允许奇数路线。

奇数路线最中心的随从向外移动时，如果两侧都满足移动条件，使用 GlobalRuleRng 等概率选择方向；零个或单个候选不消费样本。正中心没有向内的相邻路线，因此即使配置优先向内，最终两个候选都向外时也应用这条规则。随机调用排序、候选排序、调用键、记录及原子提交遵循 [ADR-005](005-global-rule-rng.md)。

先选定方向，再按目标槽位构造完整冲突组。无效移动不参与槽位竞争；赢家得到 Applied，优先级落败者得到 Rejected（`movement-priority-lost`），全部失败得到 Rejected（`slot-conflict`）。无冲突时正常移动。

每个随从只尝试选定的一个目标，竞争失败后留在原位，不重选另一侧。槽位竞争本身不消费 RNG；方向选择已经消费的样本在普通争用失败时保留，整帧规则失败时才与移动一起回滚。

## 例子

- 六条路线编号为 0–5，来源 0、2 争用第 1 路：centerFirst 选择来源 2，outsideFirst 选择来源 0，allFail 则两者都不移动。
- 来源 2 同时可去 1、3：outwardFirst 选 1，inwardFirst 选 3。
- 五条路线编号为 0–4、使用 allFail 时，正中心第 2 路若可去 1、3，则随机选一侧，再与其他移动一起裁决目标槽位。

## 边界

本决策定义系统自动移动。P7 的召唤、移动与敌我综合槽位冲突另行定义；RNG 的稳定排序只分配随机样本，不赋予移动胜负优先级。
