# EOTA · 界面设计规范

本文件是客户端所有界面的共同依据。改界面前先读这里；新增控件时优先复用这里的类（`GameTheme.tres` 中的 theme type variation），不要就地写颜色和字号。

## 1. 目标：视线不流浪

一次只回答一个问题。任何一个界面，玩家应该能立刻回答：**"我现在要看哪里、要做什么？"**

- **一个视觉焦点。** 每屏只有一个"最亮/最大"的元素（战场是手牌与提交按钮，大厅是当前页面主区，构筑是牌组内容）。
- **操作与信息聚集。** 同一个操作的按钮、它的状态、它的结果放在一起；不要让玩家在屏幕两端来回找。
- **三级信息，权重必须拉开。**
  | 层级 | 内容 | 处理 |
  |---|---|---|
  | 主 | 决策与结果：可用的手牌、英雄生命、费用、主按钮、当前回合与阶段 | 大字号（28–40）、高对比、占主要面积 |
  | 次 | 支撑信息：牌组名、路线标签、对手信息、计时 | 中字号（16–18）、常规对比 |
  | 末 | 说明、诊断、版本、协议明细、日志 | 小字号（12–14）、低对比；能收纳就收纳（折叠／次级页签／Tooltip） |
- **不重复。** 同一个数字不在两处都放大。卡面已印的数值不再用文案复述。
- **留白服务于层级。** 空白不能只是"没排满"；主区居中或成组，边缘留白比中间缝隙大。

## 2. 色板

深底 + 羊皮纸卡片 + 黄铜强调。**同一语义只用一个颜色**，颜色不再承担装饰作用。

| 语义 | 色值 | 用途 |
|---|---|---|
| 底 `Base` | `#12161b` | 窗口底色 |
| 面板 `Surface` | `#1b2128` | 面板、栏 |
| 面板（抬升）`SurfaceRaised` | `#232b34` | 需要突出的卡片、输入框 |
| 描边 `Outline` | `#2f3a45` | 常规分隔与描边 |
| 描边（强调）`OutlineStrong` | `#46545f` | 聚焦、可交互边界 |
| 文本 `Text` | `#e6edf3` | 正文、数值 |
| 文本（次）`TextMuted` | `#9aa7b2` | 说明、次要标签 |
| 文本（禁用）`TextDisabled` | `#5f6b76` | 不可用状态 |
| 强调 `Accent` | `#d8b46a` | 主按钮、当前选中、可操作高亮 |
| 强调（深）`AccentInk` | `#1a1509` | 强调色上的文字 |
| 正 `Positive` | `#6fd08c` | 增益、恢复、增加 |
| 负 `Negative` | `#e8796a` | 伤害、损失、减少 |
| 信息 `Info` | `#6fb3d8` | 费用、以太、中立提示 |
| 我方 `SideSelf` | `#2b3a4a` | 己方半场底 |
| 敌方 `SideOpponent` | `#3a2b2b` | 对手半场底 |

规则：

- 金色只用于"可操作／已选中"，不用于静态装饰。
- 己方蓝、对手红仅用于半场底色与英雄面板，不用于卡牌本身。
- 卡片保持羊皮纸色（`Card`），在深底上自然成为焦点。

## 3. 字阶

| 名称 | 字号 | 用途 |
|---|---|---|
| Display | 40 | 页面标题、英雄生命、费用 |
| Title | 28 | 区块标题、牌组名 |
| Body | 18 | 正文、按钮、卡名 |
| Label | 16 | 次要标签 |
| Small | 14 | 说明、提示 |
| Micro | 12 | 版本、诊断、脚注 |

权重靠**字号 + 颜色**拉开，不靠加粗堆叠。数字用等宽感（数值右对齐、不随位数跳动）。

## 4. 间距与形状

- 间距阶：`4 / 8 / 12 / 16 / 24 / 32`。同一层级内保持一致。
- 圆角：面板 10、按钮 8、卡牌 12、徽章 999（圆形）。
- 描边统一 1px；强调元素可用 2px 或外发光，但一屏不超过两处。
- 触摸目标最小 40px 高；主按钮 56px 高。

## 5. 主按钮与次按钮

- **主按钮**（`PrimaryButton`）：每屏最多一个。金底深字，高 56，字号 20。
- **次按钮**（`Button`）：深底浅字，高 40。
- **工具按钮**（`ToolButton`）：仅图标或短词，高 32，低对比，放在角落。
- **页签**（`NavButton`）：左侧导航，选中态金底深字，未选中透明。

## 6. 实现清单（`GameTheme.tres` + `Ui.cs`）

场景只允许使用下表中的 theme type variation；没有合适的就新增 variation，不要在场景里写 `theme_override_colors`。`Ui.cs` 里的静态色值只给代码绘制的元素（动画、`RenderingServer` 清屏、卡面高亮）使用。

| 类别 | variation | 说明 |
|---|---|---|
| 面板 | `Panel` / `Raised` | 常规面板／抬升面板 |
| 容器 | `PanelContainer`（默认用 `Panel`）、`RaisedContainer`、`CardBoxContainer`、`SlotContainer`、`FieldSlotContainer`、`DropZone`、`LanePanel` | 带边框的容器；`DropZone` 专用于拖放目标（内凹、低对比） |
| 半场 | `HeroSelf` / `HeroOpponent`（含 `*Container`） | 己方蓝底、对手红底，仅用于英雄面板 |
| 卡牌 | `Card` / `Art` / `Cost` / `Attack` / `Health` / `Slot` / `FieldSlot` | 卡面与徽章 |
| 按钮 | `PrimaryButton` / `Button` / `ToolButton` / `NavButton` | 见第 5 节 |
| 文本 | `Display` / `Title` / `Subtitle` / 默认（Body）/ `MutedLabel` / `Hint` / `Micro` | 见第 3 节；`Subtitle` = 20 用于卡牌详情标题 |
| 页签 | `TabContainer` / `TabBar` 的四个 `tab_*` 样式 | 四个样式的 `content_margin` 必须完全一致（`--smoke-interactions` 会检查） |

## 7. 各界面要点

- **大厅**：左导航只做导航（选中态明显）；主区顶部一个页面标题＋一句说明，中间成组表单，底部唯一主按钮。导航之外的说明放右侧或折叠。
- **战场**：见第 8 节的分带表——手牌与提交是焦点，其余全部降级。
- **图鉴／工坊**：主体是网格，筛选与搜索在一条工具条内；右侧详情固定宽度；数量、费用等关键数字放大。
- **设置／协议**：表单是固定宽度（760）居中的两列；取值控件不拉伸；只读项降到 Small 且低对比。
- **编辑器**：三页签（属性／效果／完整 JSON），预览固定在右，校验信息紧贴预览下方。

## 8. 战场分带（`BattleScreen.tscn`）

设计坐标系固定 1600×1000。战场分四条横带，每条只做一件事：

| 纵坐标 | 区域 | 内容 |
|---|---|---|
| 8–58 | 工具栏 | 返回、回合信息（20）、倒计时、AI 状态、全部次要按钮（`ToolButton`） |
| 68–620 | 主战区 | 左栏 20–200（双方英雄 180×216 + 费用徽章）、六路战场 214–1310、卡牌详情 1324–1580 |
| 630–694 | 决策区 | 提交回合（300×64 `PrimaryButton`）、全局法术投放区、已规划队列 |
| 702–996 | 手牌区 | 手牌（176×248，最大最亮）与底部一行 `Hint` |

约束：

- 一路外侧宽 176（内边距 6，槽位净宽 152 = `MinionTile` 宽度），间距 8；六路共 1096，与战场宽度相等，**六路必须全部可见、不出现横向滚动**（`--smoke-ui-review` 会检查）。12 路的测试协议才允许滚动。
- 手牌区高度 268 高于卡牌 248，保证出现横向滚动条时卡牌仍不被裁切（`--smoke-ui-review` 会检查）。
- 左栏自上而下是对手 → 费用 → 自己：与战场上下半场方向一致，视线不需要折返。

## 9. 检查清单

改完任一界面自查：

1. 3 秒内能说出"我现在该做什么"吗？
2. 一屏里最大的元素是不是当前最重要的信息？
3. 有没有一个数字/按钮同时出现在两处并被同等强调？
4. 说明性文字是不是都能再小一级或收进 Tooltip？
5. 用键盘 Tab 走一遍，焦点顺序是否顺着视线方向？
6. 场景里有没有绕过 variation 直接写死颜色/字号？
