# EOTA v2 客户端功能与操作

更新于 2026-09-18。本文说明客户端里有哪些功能、每个界面怎么操作，以及数据存在哪里。

**与新手教程的分工**：九阶段结算、战斗、关键词、以太与共鸣、充能、构筑与胜负规则由 [新手教程](BeginnerGuide.zh-CN.md) 讲解；本文只讲"界面能做什么、怎么点"，不重复规则细节。规则以当前对战协议、卡牌定义和 [ADR](ADR/README.md) 为准。

制作自定义卡牌请阅读 [Mod 开发者 JSON 编写指南](CardJsonDesignGuide.zh-CN.md)，可复制的源文件见 [教学示例](Content/Examples/README.zh-CN.md)。

## 大厅与九个页面

启动后进入大厅，顶部标签依次是：

| 页面 | 用途 |
|---|---|
| 本机双人 | 两人共用一台设备轮流规划并提交 |
| 加入服务器 | 用邀请地址加入别人开的房间 |
| 本机开服 | 在自己电脑上开房间，把邀请交给对手 |
| 卡牌图鉴 | 浏览全部基础卡与衍生卡，查看详情 |
| 牌组工坊 | 新建、编辑、保存和删除自己的牌组 |
| 对战协议 | 调整规则参数，影响构筑与新对局 |
| 对局回放 | 打开保存的对局，逐帧回看 |
| 人机对战 | 与简单／普通／困难 AI 对战 |
| 卡牌编辑器 | 编辑自定义卡牌并打包内容包 |

底部状态栏显示最近一次操作的结果或错误原因，多数问题看这里即可。

## 四种开局方式

### 人机对战

1. 选择你的牌组、AI 对手牌组与难度（简单／普通／困难）。
2. 按需填写随机种子，或点击「重随」换一个。
3. 点击「开始人机对战」。

你固定使用玩家一席位，AI 使用玩家二：AI 会自行换牌、规划和提交，你不需要替它操作。对局中上方会显示 AI 当前状态（思考中／等待你提交等），它出错时状态栏会给出原因。返回大厅或重新开始会先停止旧的 AI。

### 本机双人

1. 分别为玩家一和玩家二选择牌组，设置种子。
2. 两位玩家各自规划并提交；一方提交后点击「切换席位」。
3. 交接界面会遮挡手牌，需由下一位玩家点击「我是玩家X，继续对局」后才展示其手牌。

### 本机开服（联机）

1. 设置房间名、端口（1024–65535）、自己的参考牌组、对战协议，以及换牌与每回合的提交时限（不限时／30／60／120／180 秒）。
2. 默认只监听本机；勾选允许局域网加入后对外监听。
3. 点击「启动服务器」，状态变为可加入后，可以「自己加入」或复制对应席位的邀请：
   - 「复制玩家二邀请」给对手；
   - 「复制观战邀请」给旁观者（观战没有手牌与提交权限）；
   - 「复制玩家一邀请」可交给另一位玩家使用房主席位。
4. 「停止服务器」会断开所有参与者；「恢复上次房间」会重新读取原协议、原时限、已锁定牌组与日志。

开房间时**不需要**知道对手的牌组，对方加入时自行选择。

### 加入服务器

1. 粘贴完整邀请地址。
2. 选择自己的牌组，点击「核对房间」查看本局完整协议明细。
3. 确认协议与牌组后等待双方就绪，自动进入战场。

邀请地址里包含席位凭据，只应交给对应玩家；凭据位于地址的 fragment 部分，不会作为查询参数发出。

## 对战协议

进入「对战协议 → 构筑与疲劳」可以修改以下设置，保存后用于构筑、人机、本机双人和新建房间；**已开始的房间继续使用开服时确定的协议**。

| 项目 | 含义 | 默认值 |
|---|---|---|
| 牌组张数 | 每位玩家牌组必须恰好达到的总张数，范围 1–256 | 40 |
| 每种已选卡最少张数 | 某个卡牌 ID 加入牌组后至少需要的副本数；不要求所有卡都入组 | 1 |
| 每种卡最多张数 | 每个卡牌 ID 的副本上限，最多 256 | 3 |
| 构筑规则 | 正常、仅本职业、无限制 | 正常 |
| 疲劳规则 | 不疲劳、递增伤害 1、2、3…、疲劳即死 | 不疲劳 |

- 「正常」允许本职业与中立卡；「仅本职业」排除中立及其他职业；「无限制」允许任何职业的基础卡。三者都不直接开放衍生卡或测试卡。
- 修改协议不会擅自删除已保存牌组中的卡：不符合要求的条目会标红，由你自行修正；保存和开始对局时会再次校验。
- 「填入默认牌组」按当前协议生成；若当前卡池无法满足所设张数与副本限制，先调整协议或补充基础卡。

协议页按分组列出全部参数，其余只读项（版本与结算限制、随机与编码版本等）仅供核对，不可编辑。保存前会经过正式协议编译器校验，不合法则不保存并给出原因。

## 牌组工坊

- **新建**：选择职业，再选「起始牌组」——空白牌组或本职业的三个体系模板之一。模板按默认 40 张规则设计，不符合当前协议或启用卡池的模板会自动隐藏。
- **编辑**：左侧卡池按当前协议与所选职业自动筛选，点击卡牌加入牌组，右侧列表按费用排序，点「−」移除。卡池顶部可搜索。
- **保存**：填写牌组名称后保存；同名会提示更换。返回列表保留本次运行的未保存草稿，只有点击保存才写入文件。
- **删除**：自建牌组与未保存草稿右上角有「删除」，确认后连同保存文件与草稿一起移除；内置默认模板始终保留。
- **重命名**：更新同一个保存文件，不留下旧名称副本。

当前每个职业有 50 张可构筑基础卡与 2 张衍生卡，另有 22 张共享中立卡。各体系思路与完整牌表见 [十五套体系牌组](Content/ArchetypeDecks.zh-CN.md)。

## 卡牌图鉴

- 按职业筛选或搜索卡名与效果，图鉴按「职业 → 费用」排列。
- 悬停卡牌会显示该卡关键词的简要说明（悬停说明只讲关键词，卡面的数值与描述已经在卡上）。
- 点击锁定详情并在右侧展开；再点一次取消。衍生卡从基础卡详情的右下角缩略图进入，可随时返回原卡。

图鉴展示的是**原型数据**：只显示最大生命，不含当前生命、实例身份等对局信息。

## 抽牌、疲劳与满手

具体数值由协议决定，行为如下：

- 疲劳按**每位玩家自己的空牌库抽牌次数**累计，不在回合切换或重新连线时重置；牌库刚好抽空不会立刻疲劳，下一次尝试抽牌才触发。
- 「不疲劳」抽不到牌也不扣生命；「递增伤害」按 1、2、3… 依次扣英雄生命；「疲劳即死」直接斩杀该玩家英雄，当前帧结束后统一判定胜负。
- 抽走最后一张牌本身不触发斩杀；同帧还要求继续抽牌时空抽立即触发。斩杀不被同帧治疗抵消，也不中断该帧其他结算；双方在帧结束同时死亡则判平局。
- 手牌满时，有牌可抽仍按烧牌处理；牌库已空则照常触发疲劳。牌库有牌但没有符合筛选条件的牌不算空牌库；生成卡牌不计作抽牌。
- 疲劳次数保存在对局状态、断点与回放中，可在英雄信息的提示中查看。

## 战场操作

- **换牌阶段**：点击手牌标记要替换的牌，「确认换牌（N 张）」显示当前选择；不选任何牌直接确认即保留全部起手。
- **规划阶段**：点击手牌后点选高亮路线，或把卡拖入路线。已部署的牌以高亮预览显示，点击可撤回。法术按路或「全局法术」区域放置。
- **提交**：规划完成后点击提交；双方都提交后才开始结算。提交后不能再修改本回合规划。
- **右侧面板**：悬停或点击场上卡牌时显示卡图与关键词说明；「卡牌详情」区域随悬停内容更新。
- **动画控制**：可暂停、倍速与跳过。它们只改变观看方式，不改变任何结算结果，也不影响服务器计时。

限时房间里战场左侧显示提交倒计时：换牌到期保留所有未确认手牌，规划到期保留已经部署的牌并自动提交。暂停或倍速不会暂停对局计时。

## 联机确认与断线

加入者先「核对房间」查看完整协议，再确认自己的牌组。服务器按房间协议检查张数、副本、职业、来源与卡牌定义；双方都通过才开始。参考牌组只是建议，确认之后该席位本局的牌组才锁定。

- 双方可以使用不同牌组：只要求两个牌组用到的全部卡牌及递归关联卡牌定义一致，未用到的卡可以不同。
- 界面不会向房主泄露对手的完整牌组；房间描述也不公开对手牌组。
- 短暂断线会自动重连并补播未收到的战斗帧；历史不可用时直接恢复当前战场。
- 战场上方「导出诊断」把本机记录保存到 `user://diagnostics/`，断线时同样可用，便于排查同步问题。

## 对局回放

- 战场中的「保存回放」把当前对局写入用户目录的 `replays/`。
- 「对局回放」页选择已保存的回放或直接填文件路径，点击「载入回放」。
- 载入后可用进度条跳转任意帧；播放速度、暂停与跳过同样只影响观看。

回放通过正式内核重新执行命令，并对每一帧的状态、回执、事件与随机数逐项校验；因此拖动到某一帧看到的结果与当时一致，校验不一致会直接报错。

## 卡牌编辑器

「卡牌编辑器」用于制作自定义卡牌与内容包，不修改内置卡池。

- **基本属性**：卡名、ID、类型、职业、来源、费用、攻击／最大生命、场地耐久（永久场地禁用此框）、法术速度与范围、标签、插图路径、说明。
- **效果 JSON**：编辑 `effects`、`keywords`、`storedCharge`、`preventsActiveAttacksInLane` 等能力字段；不支持其他属性，写错会直接报错。
- **完整 JSON**：查看并编辑整张卡牌的 V2 文档，适合批量调整。
- **校验预览**：修改约 0.4 秒后自动刷新预览；也可点击「校验预览」立即校验。不合法时右侧预览清空，错误原因显示在下方。
- **保存**：写入用户目录 `content/draft.eotapack.json`，不覆盖 `Content/Source` 或 `Content/Generated`。新建／复制／删除／恢复内置只作用于编辑包；被其他卡引用的衍生卡不能直接删除。
- **导出**：「导出卡牌」保存当前卡及其递归关联卡与文字；「导出内容包」保存全部编辑内容。
- **内容包管理**：「导入并合并卡牌」按 ID 合并单卡包或整包（同 ID 替换，其余保留）；导入后需单独启用。「启用编辑中的内容包」会编译并核对规则哈希，复制为 `content/active.eotapack.json`；「切回内置内容包」恢复默认。

自定义内容可用于本机、人机与开服。联机只要求双方牌组涉及的卡牌与递归衍生卡的规则一致，不要求整个卡池相同；只改名称／说明不会改变规则哈希。服务器不接受客户端上传的数值或效果覆盖房间规则。

**注意**：启用自定义内容包后，新对局使用它，但**已启动的服务器仍使用开服时的内容快照**。

## 存档与数据位置

所有用户数据保存在 Godot 用户目录（Windows 为 `%APPDATA%\Godot\app_userdata\EOTA v2\`）：

| 位置 | 内容 |
|---|---|
| `decks/` | 保存的牌组 |
| `replays/` | 保存的回放 |
| `protocol.json` | 当前对战协议 |
| `content/draft.eotapack.json` | 编辑器草稿 |
| `content/active.eotapack.json` | 已启用的自定义内容包 |
| `content-selection.txt` | 当前启用的内容包路径 |
| `rooms/` | 本机开服的房间存档 |
| `diagnostics/` | 导出的诊断记录 |

更新游戏版本不会清空这些数据；删除牌组只影响对应文件与草稿。

## 窗口与显示

推荐窗口 1600×1000，也可使用 1280×800 或 1280×720。战场在 6 路与 12 路协议下都保持固定场景与双方槽位，手牌与路线可滚动；以太按玩家独立绘制，0 级不显示图标。

## 已知边界

- 协议处于内部测试期，只维护当前格式：旧牌组、旧回放或旧内容包不会自动升级，升级后可能需要重新保存或重新录制。
- 卡池为原型期实验设计，平衡性未经验证；数值会随迭代调整。
- 本机开服信任房主运行的服务器程序，不提供第三方可信服务器或远程程序证明。
