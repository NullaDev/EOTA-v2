# ADR-006：Parallel、Sequence 与单帧语义

- 状态：Accepted
- 日期：2026-09-04
- 接受日期：2026-09-06

## 直观解释

`Parallel` 表示“这些事发生在同一个时点”。所有子效果都读取动作开始前的同一份状态，先收集结果，再一起提交；数组顺序和玩家遍历顺序不能改变结局。

`Sequence` 表示卡牌文本明确要求“先做 A，然后做 B”。A 先在一帧中结算并产生回执，B 在后续帧执行，而且只能使用 A 的回执明确公开的结果。

例如：

- “对两个随从各造成 3 点伤害”使用 Parallel；两个伤害都读取同一战场快照。
- “召唤一个随从，然后使它获得 +2/+2”使用 Sequence；第二步从召唤回执取得真正召唤成功的 `EntityId`。

## 帧管线

每个结算帧执行固定管线：冻结快照、求值全部就绪工作项、产生 Intent、构造完整冲突组、归约、原子提交、生成 Receipt/DomainEvent、规划下一帧。

- `Parallel` 的所有子节点读取同一 FrameSnapshot，并把 Intent 合入当前帧。
- `Sequence` 的后一步成为后续帧 Continuation。
- `IfElse` 的条件只读当前快照。
- 事件触发器只能从提交后的 DomainEvent 创建，不能递归插入当前调用栈。
- Selector 的目标集合按稳定 ID 规范排序。
- 每个被赋予 IntentId 的 Intent 恰好产生一份 Receipt，包括空目标、NoOp、Rejected 和 Error。

战斗吸血是系统战斗帧的一项派生贡献，不作为伤害后的普通触发器：所有路线对英雄的实际战斗伤害确定后，对应吸血治疗与这些伤害进入同一个最终战斗原子帧，统一归约后才检查英雄死亡。因此吸血可以抵消本帧其他路线造成的致命伤害；双方最终生命仍都小于等于 0 时才判平局。

战斗宣告、先攻和最终伤害的具体分帧与关键词时点见 [ADR-014](014-combat-damage-frames.md)。

## Sequence 结果策略

| 前一步结果 | 后续行为 |
|---|---|
| `Applied` | 继续，并开放成功输出。 |
| `PartiallyApplied` | 继续，只开放实际成功部分的输出。 |
| `NoOp` | 继续与前一步输出无关的节点；需要缺失输出的节点稳定产生 `NoOp`。 |
| `Rejected` | 停止当前 Sequence 分支，不影响同帧其他独立分支。 |
| `Error` | 停止全部规则推进，使比赛进入 `Failed`；这是规则数据或引擎不变量错误，不是普通玩法失败。 |

“目标死亡所以没有命中”“牌库为空”“容量不足”等预期玩法结果不得使用 `Error`，而应使用可诊断的 `NoOp`、`Rejected` 或 `PartiallyApplied`。
