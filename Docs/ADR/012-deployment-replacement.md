# ADR-012：随从与场地的部署替换权限

- 状态：Accepted
- 日期：2026-09-07
- 接受日期：2026-09-07
- 来源：从 [ADR-010](010-p4-system-gameplay.md) 拆分，保留已确认语义。

## 背景

占用中的战场槽位能否再次部署，需要由明确的关键词授权；替换造成的离场不能混同死亡。

## 决定

- 每方每路分别只有一个随从槽和一个场地槽。规划时拒绝重复预约同一槽位。
- 新对象带 `replace`，或原对象带 `replaceable`，任一条件成立即可替换本方对应槽位的已有对象。
- 随从和场地使用相同的授权规则；有限和永久场地均适用。关键词默认为空，默认不允许替换已有对象。
- `replace` 与 `replaceable` 不能互换：新对象仅有 replaceable，或旧对象仅有 replace，不授予替换权限。
- 规划入口与实际部署 reducer 都检查替换权限。

旧实体生成 Replace Tombstone、进入弃牌，只产生 EntityLeft，不产生 EntityDied；新实体分配新 EntityId，使用自己的初始身材或生命周期及关键词。普通规划部署使用已存在的入场卡实例，不因替换额外复制该卡实例。

实体身份遵循 [ADR-002](002-stable-identities.md)，替换的生命周期事实与观察窗口遵循 [ADR-007](007-lifecycle-and-tombstones.md)。

## 内容契约与边界

V2 场地可写 `"keywords": ["replace", "replaceable"]`，也可只设置其中一个或省略。场地仅支持这两个关键词；未知关键词和随从专用关键词会被内容编译器拒绝。关键词规范去重、排序后进入内容与实体状态哈希。

本决策定义部署时的替换权限，不定义 P7 的 Return、Replace、Banish、Transform 综合冲突裁决。
