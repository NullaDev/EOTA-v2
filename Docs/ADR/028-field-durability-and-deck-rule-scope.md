# ADR-028：场地强度与耐久统一、按对局卡牌校验规则

- 状态：Proposed（按 2026-09-13 用户反馈用于开发版；公开协议尚未冻结）
- 日期：2026-09-13

## 场地

场地的强度就是耐久，有限场地使用 `lifetime.energy`。它决定卡面的耐久徽章、每回合消耗与耗尽离场。永久场地使用 `lifetime.kind = permanent`，没有可编辑耐久。

数值效果使用 `fieldEnergy`；表达式通过 `source.energy`、`target.energy`、`event.energy` 读取相应有限场地的耐久。内核数值归约、权威状态和公开投影均使用同一份值；永久场地不能修改耐久。

禁止本路主动攻击、蓄能、关键词与充能／触发效果都放在编辑器“效果 JSON”对象中，对应既有字段 `preventsActiveAttacksInLane`、`storedCharge`、`keywords`、`effects`。这里只调整作者界面的组织方式，不将被动能力伪装成触发效果。

## 对局校验范围

服务器冻结自己的完整规则包，实际执行使用该定义。客户端准备时必须提交自身已编译内容的逐卡规则哈希清单（至多 2048 项），服务器只比较双方卡组 ID 并集及其规则引用的传递闭包。闭包包含生成、召唤、变形／替换目标，以及条件、循环、序列、重定向和附加效果内部的引用；去重后可处理循环引用。抽牌、复制与窃取来自本局既有卡牌，不会扩大到任意全卡池。

第一位玩家确认时检查已知卡组；第二位确认时同时重新验证两个席位对完整闭包的定义。任一缺失或不一致，第二份准入不落盘、对局不创建；第一位可同步卡牌后用原锁定牌组重新确认。恢复 admission 文件时重新执行同样的双向校验。未使用、未引用的卡牌可不同、缺少或额外存在；名称、说明和插图不参与规则哈希。

哈希清单不会发送给另一位玩家，房间描述只返回自己的锁定／建议牌组，不公开对手卡组或闭包列表。准备报文限 512 KiB，普通 WS 命令仍限 64 KiB。缺少清单即拒绝准入。

房间 RuleContentHash、RoomSettingsHash、WS 握手与重连继续绑定服务器冻结包。全包哈希在此用于识别同一权威房间，并不要求玩家本地全包相同。客户端仍不能上传数值或效果覆盖规则；该机制不评估平衡性，也不证明房主服务器程序可信。

## 导出

单卡导出使用相同闭包，包含相关卡牌的 V2 源定义和必要本地化；全包导出包含编辑包全部卡牌。两者都是可校验的 `.eotapack.json`。导入按 ID 合并、同 ID 替换，保留其他卡牌；启用仍是单独操作。插图继续引用随游戏附带的资源路径，不嵌入外部图片。
