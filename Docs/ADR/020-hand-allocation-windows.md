# ADR-020：手牌容量与牌库身份分配

- 状态：Proposed
- 日期：2026-09-09
- 承接：ADR-009；替代 ADR-015 的日常抽牌实现边界

## 背景与取舍

历史设计同时要求整个宏观阶段回手优先、Sequence 读取已提交结果。若较晚的因果帧才产生回手，前一帧的抽牌可能已经决定召唤、伤害或新触发，阶段级重算需要撤销这些结果。本开发提案选择提交稳定性，容量窗口为同一原子帧中的全部就绪请求；不将较晚请求追溯加入已提交窗口。

## 决定

按玩家统一收集 Return、Generate、Draw；容量优先级为回手 > 生成 > 抽牌。同级全部放得下或完全没有空位时不采样；只有部分能进入时，用全局 RNG 从稳定候选集合中无放回选取，记录每次选择。

抽牌在容量竞争前按 `DrawAllocationKey(SourceCardId, EffectId, Ordinal)` 分配牌库顶部身份；筛选抽牌拿剩余牌库中第一个满足类型、职业和标签条件的实例。并列相同 key 以稳定 IntentId 排序。普通新回合抽牌也发出相同 HandCardIntent，使用系统来源键。

- 成功回手删除旧实体，按当前卡牌原型新建手牌实例，重置实例增益；容量不足时原实体在该帧死亡清理中死亡，产生 EntityDied 与 EntityLeft，不创建手牌。回执仍为 Rejected／hand-capacity，Removed 记录死亡实体；依赖回手成功的 Sequence 停止，死亡／离场触发照常调度。
- 成功生成才分配新身份；失败生成记录未创建的卡牌原型。
- 抽牌无论容量竞争结果如何都从牌库移出；失败抽牌进入 Removed，保留 CardBurned 事实，不进入 Discard。牌库非空但筛选无匹配时产生 NoOp；空牌库上的抽牌请求按协议执行不疲劳、递增伤害或斩杀，胜负在帧结束后判定。
- 回执分别记录移出牌库、进入手牌、烧毁、未创建的具体身份。卡牌区修改仅修改选中的实例，规划费用和部署读取修改结果。

开局及换牌仍按 ADR-009 的 bootstrap 合同执行，不进入日常容量窗口。此提案尚非人工确认的公开协议规则。
